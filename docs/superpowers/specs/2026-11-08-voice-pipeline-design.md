# Голосовой конвейер v2: произношение отдельно от тембра

Дата: 2026-11-08. Статус: утверждён пользователем (устно, разделы 1–6), ждёт реализации.

## 1. Зачем

Жалобы, которые решает этот проект:

- **Акцент.** Все три движка 1.0.0 клонируют голос с английских записей актёра и говорят по-русски.
  У зеро-шот клонировщиков тембр и фонетика образца сцеплены — акцент образца переносится (это
  признают документации VoxCPM2, OmniVoice, Chatterbox). Полное дообучение Qwen на английских
  записях персонажа закрепляет английский выговор ещё сильнее.
- **Один персонаж звучит разными людьми.** Каждая реплика клонируется заново со случайностью;
  часть реплик персонажа лежит в чужих «разговорах» (группы из файлов игры), и профиль голоса
  собирается из чужих записей.
- **Долгое обучение и 4 ГБ на персонажа.** Полное дообучение Qwen даёт чекпойнт ~4 ГБ и часы работы,
  а акцент не убирает.

Не входит в этот проект (отдельные спецификации): смех/кашель/эхо и акустика (B), уборка диска
после установки (C), пауза и «остановить и удалить» (D), новый интерфейс (E).

## 2. Устройство: три ступени

```
текст (субтитры/перевод → ruaccent → режиссёр)
  → 1. Русская речь донорским голосом       (speech source)
  → 2. Тембр персонажа                       (timbre: RVC-модель персонажа | нет)
  → 3. Подгонка под оригинал                 (fit: как сейчас, performance.compose)
  → контролёр (как сейчас) → одобрение → установка
```

Правило: **произношение всегда рождается от русского образца**, поэтому ступень 1 не знает
английских записей. Тембр персонажа добавляет ступень 2 — одна обученная RVC-модель на персонажа
на всю игру: голос не «плавает» по построению. Эмоцию задаёт ступень 1 (пунктуация режиссёра,
intensity → температура, донорский образец «спокойно / зло / грустно»), тембр при этом не меняется.

Исключение — **эпизодические персонажи**: у них мало записей для обучения тембра, они идут по
«быстрому пути»: кросс-языковое клонирование с английской записи (как в 1.0.0) движком-победителем
стенда, с риском лёгкого акцента. Настройка `episodic_mode = clone | donor` позволяет вместо этого
озвучить их донорским русским голосом без акцента (тембр чужой).

### 2.1 Уровни персонажей

`tier(char)`:

- `main` — речи персонажа ≥ `timbre_min_seconds` (по умолчанию 120 с) и реплик ≥ 12 → полный путь.
- `episodic` — остальные.

Пользователь может переключить уровень вручную на экране «Голоса» (`timbre_override[char] = train |
episodic`). Число обучаемых не ограничено сверху: обучение идёт по убыванию числа реплик, время
показывается заранее.

### 2.2 Ступень 1 — источник русской речи

Единый интерфейс бэкендов (как сейчас `tts.synthesize`):

```
synthesize(backend, texts, refs, max_seconds, params, seed) -> [(wav, sr)]
refs[i] = {"audio": путь, "text": расшифровка | None, "language": "ru" | "en", "speaker": имя | None}
params = {"instruct", "temperature", "intensity", "emotion", ...}
```

Каждый бэкенд объявляет `capabilities`: `stress` (acute | plus | none), `style` (punct | instruct |
tags), `nonverbal_tags` (bool), `clone` (bool), `cross_lingual` (bool), `env` (папка среды или None),
`license_ok_commercial` (bool). Кандидаты:

| ключ | что | ударения | эмоция | лицензия |
|---|---|---|---|---|
| `qwen_ru` | Qwen3-TTS RU-stress (LoRA siriusfreak), клон с *русского* донора + расшифровка (ICL) | acute | пунктуация, intensity→temp, донор по эмоции | Apache-2.0 |
| `qwen_custom` | Qwen3-TTS CustomVoice: готовый диктор + instruct, русский текст | ё только | instruct | Apache-2.0 |
| `silero` | Silero v5.6 ru (aidar/baya/kseniya/xenia/eugene), SSML | свои | нет (только темп/высота) | CC BY-NC 4.0 — только по явному выбору, с пометкой |
| `omnivoice` | OmniVoice (k2-fsa), клон с русского донора, теги `[laughter]`, `[sigh]` | none | теги + донор | Apache-2.0 |

Кандидаты быстрого пути (эпизодические, `cross_lingual=True`): `qwen_ru` с английского образца в
режиме x-vector (текущий `ru`), `voxcpm` (текущий), `omnivoice` с английского образца.

Какие бэкенды становятся умолчаниями — решает стенд (раздел 5), не спецификация. Обязательные для
релиза: `qwen_ru` (уже скачивается) и путь RVC. `omnivoice`, `silero`, `voxcpm` — необязательные
среды, ставятся кнопкой.

### 2.3 Донорский банк

Папка `ruvoice/donors/`: `manifest.json` + клипы `<id>_<style>.flac` (24 кГц, моно, 6–10 с).

- ~16 голосов: пол × высота (низкий/средний/высокий) × возраст (молодой/взрослый/пожилой) — не все
  сочетания, а те, что реально встречаются в играх (по 8 на пол).
- У каждого голоса три подачи: `calm`, `angry`, `sad`. Подача выбирается по эмоции реплики
  (angry/disgust → angry; sad/fearful → sad; остальное → calm). Голос один и тот же, меняется только
  манера — тембр закрепляет ступень 2.
- Поля манифеста: `id`, `gender`, `age`, `f0` (медиана, Гц), `text` для каждого клипа (нужен для
  ICL), `source` (чем сгенерирован), `license`.
- Генерация банка — скрипт `tools/make_donors.py` (Qwen3-TTS VoiceDesign/CustomVoice по текстовому
  описанию, русский текст), запускается разработчиком один раз; клипы лежат в репозитории
  (суммарно < 10 МБ, формат FLAC — в `.gitignore` исключение для `ruvoice/donors/*.flac`).
- Клипы **не** генерируются из английских записей персонажей — иначе акцент вернётся.

Подбор донора персонажу (`donors.pick(p, char)`): по типу голоса (f0 профиля → пол и высота в
пределах ±4 полутона от донора), среди подходящих — по косинусу ECAPA к профилю персонажа.
Результат закрепляется в проекте `donors[char] = {"id", "picked_at", "manual": false}` и не
пересчитывается сам (только если сбросить или изменить вручную на экране «Голоса»).

### 2.4 Ступень 2 — тембр (RVC)

Среда `runtime/engines/rvc` (Applio, MIT) остаётся в текущем виде процесса-работника (`engines/worker.py`,
класс `RVC`), но:

- **Установка из программы.** Кнопка «Установить перенос тембра» → `engines/install.py` ставит
  `requirements-rvc.txt` в `runtime/engines/rvc` через uv, скачивает Applio (релизный архив с
  закреплённым тегом/коммитом) в `runtime/engines/rvc/applio` и претрейны (`f0G40k.pth`, `f0D40k.pth`,
  `rmvpe.pt`, `contentvec`) с Hugging Face в `applio/rvc/models/...`. Ход показывается как у скачивания
  моделей. Без среды главные персонажи озвучиваются по быстрому пути с предупреждением.
- **Данные обучения.** Реплики персонажа ≥ 1,0 с после обрезки тишины, статус не `skipped`,
  `info.speech ≥ 0.5` если есть отсев, отсортированные `_most_typical` (ближе к центру голоса),
  до `minutes` минут по уровню. 6 контрольных реплик (как сейчас holdout) в обучение не попадают.
- **Уровни** (`timbre_level`): `fast` = 150 эпох, 8 мин записей; `normal` = 300 эпох, 15 мин;
  `deep` = 500 эпох, 25 мин; `off` = никого не обучать (все по быстрому пути). Пачка 8 при ≥ 12 ГБ
  видеопамяти, иначе 4. Время считается по `data/train_speed.json` (секунд на эпоху на минуту
  записей, ключ `rvc`), до первого замера — по константе, которую я замерю на RTX 5070 Ti.
- **Высота.** `pitch = round(12·log2(f0_char / f0_donor))`, считается один раз при подборе донора,
  хранится в `donors[char].pitch`. `auto_pitch=False`, `index_rate=0`, `protect=0.5` — как сейчас.
- **Контроль после обучения** (`voices/<char>/rvc/calib/`): 6 контрольных реплик озвучиваются
  донором без тембра и донором с тембром. Модель принимается, если похожесть ECAPA с профилем
  персонажа у варианта «с тембром» выше, чем у «без тембра», и CER произношения (pron) не хуже чем на
  0,03, и медианная высота в пределах 3 полутонов от профиля. Иначе модель помечается `weak` и
  персонаж идёт по быстрому пути (`episodic_mode`), в «Голосах» видна причина. «Хуже не станет»
  сохраняется.
- **Результат:** `voices/<char>/rvc/model.pth`, `model.index`, `meta.json` (эпохи, минуты, время,
  контроль), `calib/*.wav`. Запись в проекте `voices[char] = {"method": "rvc", "pth", "index",
  "epochs", "dataset_seconds", "train_seconds", "trained_at", "val": {...}, "weak": bool}`.

### 2.5 Ступень 3 и контролёр

`performance.compose` / `audio.fit_to_original` без изменений. Контролёр без изменений, кроме
постоянства голоса:

- «русский голос» персонажа (центр ECAPA) для `main` = отпечаток калибровочных записей
  «донор + тембр» (фиксированный вектор `ru_voice[char] = {"e", "fixed": true, "floor"}`), для
  `episodic` = отпечаток профиля оригинала (как сейчас, `seed: original`).
- Бегущее среднее по сгенерированным репликам (`_ru_voice_add`) убирается: центр не дрейфует.
  Список сходств принятых реплик с центром по-прежнему копится — только для порога.
- Порог дрейфа `floor` = медиана сходств калибровочных записей с центром − `DRIFT_MARGIN` (0,12);
  для эпизодических — медиана сходств принятых реплик − `DRIFT_MARGIN`, когда их накопилось ≥ 6.

### 2.6 Детерминизм

Зерно варианта `k` реплики `id` при прогоне `take`: `seed = crc32(id) ^ (100003·(take+1) + 977·k)`.
Повторная озвучка той же реплики даёт тот же результат; «Переделать пробы» меняет `take`.

## 3. Кто говорит

`speakers.propose` остаётся. Добавляется второй проход `speakers.attach_rest(p, have, prop)`: каждая
реплика, не попавшая ни в один голос, присоединяется к голосу, если косинус к его центру ≥ `ATTACH_COS`
(0,38) и выше второго по близости хотя бы на 0,08; иначе остаётся в своей группе. Проход выполняется в
`_auto_speakers` после `apply`. Для адаптеров с надёжными говорящими (`speakers_reliable`) шаг
по-прежнему пропускается.

Экран «Голоса» (данные — API, сам экран рисует проект E; до него — минимальная таблица в студии):
персонаж, реплик/минут, тип голоса, 3 реплики на прослушивание, донор (сменить), уровень
(main/episodic, переключить), состояние тембра (обучен / слабый / не обучен / идёт обучение),
слияние и переименование (существующие `merge`, `character` PATCH).

## 4. Что уходит

- Полное и LoRA-дообучение Qwen (`ttsft.py`, `tools/qwen3-tts-finetune`, `train_tts`, `FT_LEVELS`,
  `train_levels`, `ft_setup`, `_validate_tts_voice`, `tts._use_voice`, `tts._full_generate`, модель
  `tts-tok` из наборов). Старые `tts_voices` в проектах игнорируются, их папки удаляет уборка.
- Закреплённые эталоны и пробы постоянного голоса (`identity.py`, `voice_trials.py`, маршруты
  `voice-identities`, `voice-trials`, кнопки «Закрепить голос», `voice_anchors`): их заменяют донор +
  тембр. Данные в старых проектах не трогаются, но не используются.
- Настройки: `ft_*`, `tts_finetune`, `train_limit/minutes/epochs/min_seconds`, `minor_*`,
  `voice_transfer`, `emotion_refs`, `stable_voice`, `speech_engine`. Новые: `speech_source`
  (auto | ключ бэкенда), `clone_engine` (auto | ключ), `episodic_mode` (clone | donor),
  `timbre_level` (off | fast | normal | deep), `timbre_min_seconds`. `SETTINGS_VERSION = 3`:
  при открытии старого проекта неизвестные ключи отбрасываются, новые — по умолчанию.
- VoxCPM2 остаётся только как необязательный бэкенд быстрого пути.

## 5. Стенд движков

`python -m ruvoice.enginebench --game <gid> [--chars 3] [--lines 10] --variants <a,b,…>` и кнопка в
студии «Сравнить движки». Вариант — строка `источник[+rvc]`, например `qwen_ru+rvc`, `silero+rvc`,
`qwen_custom`, `voxcpm` (для `voxcpm`/`qwen_ru_xlang` источник — английская запись персонажа).

- Набор реплик закреплён в проекте (`bench_lines`, как сейчас): 3 персонажа × 10 реплик, разные
  эмоции и длины.
- Для каждого варианта и реплики: WAV, время синтеза, `pron_cer` (wav2vec2, прокси акцента),
  `whisper_cer` (разборчивость), `ecapa_sim` к профилю оригинала (похожесть), `f0_range` (живость),
  `ratio` (длина к оригиналу).
- Результат: `bench/<метка>/index.html` — таблица «реплика × вариант» с оригиналом и плеерами,
  сводные средние по вариантам; `rows.json`. Старая «Контрольная сцена» заменяется этим.
- Первый прогон: Half-Life 2 (Source, надёжные говорящие) и Hogwarts Legacy (Unreal/Wwise) — по
  результатам и прослушиванию выбираются умолчания `speech_source` и `clone_engine`; выбор
  фиксируется в `DEFAULT_SETTINGS` и в этой спецификации (раздел 8).

## 6. Данные, API, модели

- Проект: `meta.donors`, `meta.timbre_override`, `meta.voices` (RVC), `meta.ru_voice` (фиксированные
  центры), `voices/<char>/rvc/...`, `bench/<метка>/`.
- API: `GET /projects/{gid}/voices` (экран «Голоса»), `POST /projects/{gid}/voices/donor {char, donor}`,
  `POST /projects/{gid}/voices/tier {char, tier}`, `POST /projects/{gid}/train-voice {char}` (только
  RVC), `POST /projects/{gid}/enginebench {variants}`, `POST /system/engines/install {engine}`,
  `GET /system` отдаёт `engines` с состоянием сред и бэкендов. Маршруты эталонов удаляются.
- `models.py`: `tts-ru` остаётся; `tts-custom` — необязательная; добавляются `silero-ru`
  (один `.pt`), `omnivoice` (веса), среда `rvc` с претрейнами — через `engines/install.py`, а не через
  `models.download`. Наборы (tiers): речь + контролёр + языковая модель, тембр — отдельной кнопкой,
  рекомендуемой по умолчанию.

## 7. Тесты

Без видеокарты (unittest, моки движков):

- подбор донора: пол/высота по f0, затем ECAPA; ручной выбор не перезатирается;
- уровни персонажей и ручное переопределение; миграция настроек v2 → v3;
- детерминизм зёрен; фиксированный центр не меняется от новых реплик;
- `attach_rest`: присоединение по порогу и марже, неподходящие остаются;
- конвейер `_do_generate` с подменёнными `synthesize`/`convert_timbre`: для `main` вызывается тембр,
  для `episodic` — быстрый путь; слабая модель → быстрый путь;
- контроль обучения: правила принятия/отклонения модели;
- стенд: манифест и html без синтеза (подменённые бэкенды);
- уборка: папки старого дообучения удаляются, RVC-модели нет.

С видеокартой (вручную, по чек-листу в плане): стенд на HL2, обучение одного персонажа с замером
времени, озвучка 30 реплик, установка в HL2 и откат.
